# Invites Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Matthew emails personal invites from his Gmail via an owner-only Admin → Invites tab. Each invite carries a single-use credit code that the person redeems on a hidden `/redeem` page.

**Architecture:**
- Pure text helpers (placeholders, blanks, code cleanup) live in `src/lib/invite-text.js` so the form and the server share them.
- `server/invites.js` owns the two new tables, sending through nodemailer (swappable in tests, like `usePurge`), and the single-use redeem transaction.
- Routes: owner-only cases in `netlify/functions/admin.js`, and `POST /api/credits/redeem` in `netlify/functions/credits.js`.
- UI: `AdminInvites.svelte` with an `InviteBook.svelte` popup, and `Redeem.svelte`.

**Tech Stack:** Svelte 5 (runes), Netlify functions, Postgres (Neon; `@netlify/database-dev` in tests), `node --test`, nodemailer (new).

**Spec:** `docs/superpowers/specs/2026-10-21-invites-design.md`

## Global Constraints

- Only the owner (`roleOf(id).owner`, from `ADMIN_SUBS`) may list, send, resend, cancel or forget invites, or touch templates. Admins who aren't the owner get 403.
- An invite row never stores an account id. The ledger row for a redeem uses `reason 'invite'`, `ref` NULL, `paid` false.
- The Log tab gets no entries for sends or redeems.
- Credits per invite: a whole number from 1 to 500.
- Code: 32 random bytes as 64 lowercase hex characters, stored as-is.
- Auto placeholders, case-insensitive with spaces inside the brackets ignored:
  - `[credits]` becomes the invite's credits;
  - `[redeem link]` becomes `${origin}/redeem?code=${code}`.
- Every other `[...]` is a blank. The client and server both refuse to send while any remain.
- The body must contain `[redeem link]`.
- Plain-text email from `SMTP_FROM`, via `SMTP_HOST`/`SMTP_PORT`/`SMTP_USER`/`SMTP_PASS`, with `secure` when the port is 465.
- `/redeem` is noindex, and isn't in `FIXED_PAGES`, the sitemap, the nav or Help.
- Copy:
  - bad code: "This code has already been used or isn't valid."
  - missing link: "Add [redeem link] so they can claim the credits."
- Tests run with `npm test`. Never print `.env` values. Load env with `node --env-file=.env`.
- Commit locally after each task. Don't push: Matthew OKs pushes. Before the push, the five SMTP_ vars must be added in Netlify.

## Review Focus

1. **Double clicks.** Redeem double-clicked, or the same code redeemed in two tabs at once, adds credits once. (Task 2 test `redeem twice at once adds once`.)
2. **Pasted codes.** A code pasted with spaces, line breaks or dashes, or the whole link pasted into the box, still redeems. (Task 1 test `normalizeCode`.)
3. **Placeholder spelling.** `[Credits]`, `[ redeem link ]` and `[REDEEM LINK]` are all auto-filled, not flagged as blanks. (Task 1 test `fillInvite`.)
4. **Gmail failures.** A rejected login or no SMTP settings leaves no stored invite, and the error says so plainly. (Task 2 test `send failure stores nothing`.)
5. **Non-owners.** A non-owner admin, a signed-out visitor or a suspended account is refused. (Task 2 tests `owner only`, `redeem needs an active account`.)

**Interfaces:**
- Consumes:
  - Task 1 helpers;
  - `transaction`, `database` from `server/db.js`;
  - `roleOf`, `requireActive` from `server/roles.js`;
  - `UserFacingError` from `server/chef.js`.
- Produces:
  - `requireOwner(accountId) -> role`, in roles.js. Throws `UserFacingError("Only the site owner can do that.", 403)`.
  - `useMailer(fn | null)`: `fn({ to, subject, text }) -> Promise`. With null it goes back to nodemailer built from the SMTP_ env vars.
  - `listInvites(actorId) -> { invites: [{ id, email, credits, sentAt, usedAt, canceledAt }], templates: [{ id, name, subject, body }] }`. Invites are newest first; templates are by name.
  - `sendInvite(actorId, { to, subject, body, credits }, origin) -> { id }`
  - `resendInvite(actorId, id) -> { ok: true }`
  - `cancelInvite(actorId, id) -> { ok: true }`
  - `forgetInvite(actorId, id) -> { ok: true }`
  - `saveTemplate(actorId, { name, subject, body }) -> { id }`: upserts on name.
  - `deleteTemplate(actorId, id) -> { ok: true }`
  - `redeemInvite(accountId, rawCode) -> { added, credits }`

**Migration.**
- `invites`:
  - `id BIGSERIAL PK`
  - `code TEXT UNIQUE NOT NULL`
  - `email TEXT NOT NULL`
  - `subject TEXT NOT NULL`
  - `body TEXT NOT NULL` (the filled text as sent)
  - `credits INT NOT NULL CHECK (credits BETWEEN 1 AND 500)`
  - `sent_at TIMESTAMPTZ NOT NULL DEFAULT now()`
  - `used_at TIMESTAMPTZ`
  - `canceled_at TIMESTAMPTZ`
- `invite_templates`:
  - `id BIGSERIAL PK`
  - `name TEXT UNIQUE NOT NULL`
  - `subject TEXT NOT NULL`
  - `body TEXT NOT NULL`
  - `updated_at TIMESTAMPTZ NOT NULL DEFAULT now()`
- Seed one template, "Recipe blogger", with the subject and body copied exactly from the spec's "The seed template" section. Use dollar-quoting (`$t$…$t$`).

**Behaviour.**
- **sendInvite**:
  1. Validate with the limits. Use the email regex from `server/messages.js` and a 200-character cap. Blanks in the subject or body are refused with "Fill in the blanks first: [user], …". A body without `[redeem link]` is refused with the spec copy.
  2. Insert the row with the filled subject and body.
  3. Send.
  4. If the send throws, delete the row and throw `UserFacingError("Gmail didn't take the email: <err.message>", 502)`.
  - With no SMTP settings, throw `UserFacingError("Email isn't set up yet: add the SMTP_ settings.", 503)` before inserting.
- **resendInvite**: only an unused, uncanceled invite. Sends the stored subject, body and email again and sets `sent_at = now()`. Any other invite gets "That invite was already used or canceled." (409).
- **cancelInvite**: sets `canceled_at` on an unused invite.
- **forgetInvite**: deletes the row, any state.
- **redeemInvite**: `requireActive` first. If `normalizeCode` gives "", throw the bad-code copy (404). Then one `transaction`:
  1. `UPDATE invites SET used_at = now() WHERE code = $1 AND used_at IS NULL AND canceled_at IS NULL RETURNING credits`. No row means throw the bad-code copy (404).
  2. `INSERT INTO credit_ledger (account_id, change, reason, ref, paid) VALUES ($acct, $credits, 'invite', NULL, false)`.
  3. `UPDATE accounts SET credits = credits + $credits WHERE id = $acct RETURNING credits`.

  - `send refuses blanks and a missing link`: rejects `/Fill in the blanks first: \[user\]/` and `/Add \[redeem link\]/`. Nothing is stored.
  - `send failure stores nothing`: `useMailer(async () => { throw new Error("535 bad login") })`. Rejects `/Gmail didn't take the email: 535 bad login/`. The invite count is unchanged.

A second redeem rejects `/already been used or isn't valid/`. The `credit_ledger` row has reason `invite`, ref null, paid false. `SELECT * FROM invites` has no account column.

  - `canceled and forgotten codes don't redeem; resend refuses used codes`.
  - `redeem needs an active account`: `redeemInvite(null, code)` rejects with 401, and a suspended account rejects with 403.
